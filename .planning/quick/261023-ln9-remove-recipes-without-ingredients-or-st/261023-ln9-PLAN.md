# Quick 261023-ln9: Complete recipes only

## Task 1: Saving requires title + ≥1 ingredient + ≥1 step

- **files:** `src/lib/recipes/schema.ts`, `src/app/[locale]/(app)/recipes/actions.ts`,
  `src/i18n/messages/{pt,en}.json`, `tests/unit/recipe-schema.test.ts`
- **action:** `recipeInputSchema` ingredients/steps require at least one non-blank line (after blank
  lines are dropped). Create and edit both go through the same schema in the server actions. The
  action shows a dedicated "add at least one ingredient/step" message for an empty list and keeps
  the existing max-length message otherwise. Unit tests cover empty and blank-only lists.
- **verify:** `npm run test:unit`, `npm run typecheck`, `npx eslint` on changed files.
- **done:** A recipe with no ingredients or no steps cannot be created or edited into that state.

No database CHECK constraint: the app is the only writer for members, and a constraint would also
require rewriting the many test fixtures that insert title-only rows. Can be added later.

## Task 2: E2E helpers save complete recipes

- **files:** e2e specs whose helpers save via the form with only a title.
- **action:** Fill one ingredient and one step before saving.
- **verify:** `npm run typecheck`; specs not run (the default e2e config wipes the DEV database
  behind the live demo).

## Task 3: One-off cleanup of incomplete recipes (with photos)

- **files:** `scripts/remove-incomplete-recipes.mjs`
- **action:** Service-role script reading `.env.local`. Default is a dry run that lists recipes with
  zero ingredients or zero steps and their photo count. `--apply` deletes each recipe's Storage
  objects first, then the recipe row (photo rows and creator rows cascade).
- **verify:** Dry run against DEV; the user confirms the list; then `--apply` and a second dry run
  showing zero.
