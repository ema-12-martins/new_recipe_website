    - scoreDraft(expected, actual) returns { title, ingredients, steps, critical } where each field reports the number of edits a person would need (title: normalised edit distance 0..1; ingredients and steps: counts of lines to fix, add or delete)
    - A perfect match scores zero edits everywhere
    - Missing, extra and changed ingredient lines are each counted once
    - Swapping two steps counts as a step-order error
    - extractCriticalTokens finds quantities (digits, decimals, fractions such as 1/2 and ½), units (g, kg, ml, l, dl, cl, colher, chávena, cup, tbsp, tsp, etc.) and temperatures (180 °C, 350 F) and critical errors count tokens present in expected but absent or altered in actual

Line matching: pair each expected line with its best actual line by normalised edit distance; unmatched lines count as add/delete; a paired line with distance above 0 counts as one edit. Comparison is exact (no case folding, no accent stripping).

  <files>scripts/ocr-benchmark/run.mjs, scripts/ocr-benchmark/providers/document-ai.mjs, scripts/ocr-benchmark/providers/gemini.mjs, scripts/ocr-benchmark/README.md</files>

  <action>
1. run.mjs: `node scripts/ocr-benchmark/run.mjs <provider> [--samples <dir>]`. Samples directory layout: one folder per recipe containing `page-1.jpg`, `page-2.jpg`, … and `expected.json` ({ language, title, ingredients[], steps[] }). For each recipe it loads the provider module, calls `recognize({ images: Buffer[], language })` returning { title, ingredients[], steps[] }, measures latency, calls scoreDraft, and writes `scripts/ocr-benchmark/results/<provider>-<timestamp>.json` plus a one-screen summary to stdout (mean edits per field, critical-error counts, p50/p95 latency, failures). It never prints recipe text.
2. providers/document-ai.mjs: POST to the Document AI REST `:process` endpoint of an EU processor (URL and processor id from env DOCUMENT_AI_ENDPOINT), bearer token from GCP_ACCESS_TOKEN; then map the OCR text to a draft with a simple heading and list heuristic. providers/gemini.mjs: POST the images to the Vertex AI Gemini REST endpoint of an EU region (env GEMINI_ENDPOINT) with a JSON-schema response asking for title, ingredients[] and steps[], keeping the original wording and units. Both validate the response shape and throw a typed error otherwise. Neither writes tokens or responses to disk except through run.mjs results.
3. README.md: how to lay out samples, which environment variables to set, how to obtain a short-lived access token, and the reminder that nothing under benchmark/ or results/ may be committed.
4. Add a dry-run flag `--stub` that uses a built-in echo provider returning the expected recipe so the harness can be exercised without credentials; cover it with one test in tests/unit/ocr-score.test.ts that runs run.mjs against a temporary synthetic samples folder.
