## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| New e2e browser contexts inherit the owner session | `browser.newContext()` picks up the project's owner `storageState`, so a "device" opens already signed in as the owner | advisory | Pass `storageState: { cookies: [], origins: [] }` (see `openDevice` in tests/e2e/auth-devices.spec.ts and tests/e2e/invites.spec.ts) |
| Signing out in e2e with the owner's shared session | `signOut` revokes the session that every viewport project reuses from tests/e2e/.auth/owner.json | advisory | Exercise sign-out only with a separate member on a new context, never the owner `page` |
| `getByRole("alert")` is ambiguous | The Next.js route announcer is an empty `role="alert"` element on every page | advisory | Match alerts by text: `getByRole("alert").filter({ hasText })` |
| PowerShell wildcard paths | `[locale]` / `[token]` are wildcards: New-Item/Get-ChildItem silently miss, git pathspecs fail | advisory | Use `-LiteralPath` or `[System.IO.Directory]::CreateDirectory`; in git pathspecs write `[[]locale]` |
| Impure calls during render | eslint `react-hooks/purity` rejects `Date.now()` in a component body | advisory | Compute time-dependent values in a data loader outside render (see `loadMembersData` in members/page.tsx) |
| Typing into controlled forms before hydration | WebKit typed before React hydrated and lost the text | advisory | New client forms wrap fields in `<fieldset disabled={!hydrated}>` (useSyncExternalStore) |
| Trusting gsd-tools STATE body mutations | `state.advance-plan`/`state.update-progress` cannot parse this STATE.md body; `state.begin-phase` zeroes `progress.percent` | advisory | Skip begin-phase; after each plan update STATE.md frontmatter (`completed_plans`, `percent`) and Current Position by hand. `roadmap.update-plan-progress` and `requirements.*` work |
