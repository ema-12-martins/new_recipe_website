## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| New e2e browser contexts inherit the owner session | In 01-11, `browser.newContext()` picked up the project's owner `storageState`, so every "device" opened already signed in as the owner and all 16 tests failed | advisory | Pass `storageState: { cookies: [], origins: [] }` when a test needs a signed-out device (see `openDevice` in tests/e2e/auth-devices.spec.ts) |
| `getByRole("alert")` is ambiguous | The Next.js route announcer is an empty `role="alert"` element on every page | advisory | Match alerts by text: `getByRole("alert").filter({ hasText })` |
| Running execute-phase on an agent-* branch | The cwd-drift guard (#48) refuses to execute waves there | advisory | `git switch main` and `git merge --ff-only origin/main` before `/gsd-execute-phase` |
| Typing into controlled forms before hydration | WebKit typed before React hydrated and lost the text | advisory | New client forms wrap fields in `<fieldset disabled={!hydrated}>` (useSyncExternalStore), as in sign-in-form.tsx and recipe-form.tsx |
| Trusting gsd-tools STATE body mutations | `state.advance-plan`/`state.update-progress` cannot parse this STATE.md body; `state.begin-phase` zeroes `progress.percent` | advisory | Skip begin-phase; after each plan update STATE.md frontmatter (`completed_plans`, `percent`) and Current Position by hand. `roadmap.update-plan-progress` and `requirements.*` work |
