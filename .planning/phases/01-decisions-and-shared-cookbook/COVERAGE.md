## Explicit Phase 1 exclusions

| Capability | Decision | Reason |
|---|---|---|
| OCR, image import, and source-photo storage APIs | OPT-OUT | Phase 2; D-14 remains a retention requirement for saved photo-imported recipes, not a Phase 1 integration. |
| Search and category APIs | OPT-OUT | Phase 3, outside the Phase 1 roadmap requirement set. |
| General recipe delete/restore/trash APIs | OPT-OUT | D-15 explicitly excludes these controls. D-10's per-recipe member-removal decision remains a distinct access-removal operation. |
| Push notifications, analytics, or unrelated vendor capabilities | OPT-OUT | No approved Phase 1 requirement needs them; keep family data surface limited. |
| Any identity, backend, build, submission, or store provider other than Candidate A's spike services | UNSELECTED | Candidate A approval is only for a reversible spike; no production vendor or stack is approved. |

The service names above define the spike's specific coverage target, not completed integration. The spike must enumerate actual API operations and security boundaries, prove authorized and denied family access, and capture iPhone and Android build/install evidence. Account access and platform eligibility are reported available by D-16 but remain unverified. The human package-legitimacy checkpoint approved the required spike package identities and CLI tools on 2026-10-21; no package has been installed yet.
